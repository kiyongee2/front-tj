1. 개발 환경과 프로젝트 구조

Vite로 프로젝트를 실행하고, 폴더별 역할을 이해합니다.

실행 명령

npm install       # 의존성 설치
npm install react-router-dom axios   # 추가 라이브러리
npm run dev       # 개발 서버 (http://localhost:5173)
npm run build     # 배포용 빌드

폴더 구조

src/ ├── main.jsx 진입점: <App />을 #root에 렌더링 ├── App.jsx Provider · Router · 라우트 정의 ├── App.css 전역 스타일 ├── components/ 여러 페이지에서 재사용하는 UI │ ├── Header.jsx │ └── ProductCard.jsx ├── context/ 전역 상태 │ └── CartContext.jsx ├── data/ 정적 데이터 │ └── products.js └── pages/ 라우트 단위 화면 ├── ProductList.jsx ├── ProductDetail.jsx ├── CartPage.jsx ├── Notice.jsx └── NotFound.jsx
💡 폴더 나누는 기준 pages는 "주소 하나에 대응하는 화면", components는 "여러 화면에서 쓰는 부품", context는 "앱 전체가 공유하는 상태"입니다.

전체 컴포넌트 트리

export default function App() {
  return (
    <CartProvider>            {/* ① 장바구니 상태를 앱 전체에 공급 */}
      <BrowserRouter>         {/* ② 주소(URL) 기반 화면 전환 */}
        <Header />            {/* ③ 모든 페이지 공통 */}
        <main>
          <Routes>
            <Route path="/" element={<ProductList />} />
            <Route path="/product/:id" element={<ProductDetail />} />
            <Route path="/cart" element={<CartPage />} />
            <Route path="/notice" element={<Notice />} />
            <Route path="*" element={<NotFound />} />
          </Routes>
        </main>
      </BrowserRouter>
    </CartProvider>
  );
}

2. 컴포넌트와 props

부모가 넘겨준 데이터(props)로 화면을 그리는 재사용 컴포넌트를 만듭니다.

컴포넌트는 JSX를 반환하는 함수입니다. 부모는 속성처럼 값을 넘기고, 자식은 매개변수의 구조 분해로 받습니다.

export default function ProductCard({ product }) {   // props 구조 분해
  const { dispatch } = useCart();
  return (
    <div className="card">
      <span className="category">{product.category}</span>
      <h3><Link to={`/product/${product.id}`}>{product.name}</Link></h3>
      <p className="price">{product.price.toLocaleString()}원</p>
      <button onClick={() => dispatch({ type: "ADD", product })}>담기</button>
    </div>
  );
}
  • className: JSX에서는 class 대신 className을 씁니다.
  • { }: JSX 안에서 자바스크립트 표현식을 사용할 때 감쌉니다.
  • toLocaleString(): 25000 → "25,000"처럼 천 단위 구분 기호를 붙입니다.
  • onClick={() => ...}: 함수를 전달해야 합니다. onClick={dispatch(...)}로 쓰면 렌더링하자마자 실행됩니다.

3. 리스트 렌더링과 key

배열 데이터를 map()으로 컴포넌트 목록으로 바꿉니다.

export const products = [
  { id: 1, name: "무선 마우스", category: "마우스", price: 25000, desc: "..." },
  { id: 2, name: "기계식 키보드", category: "키보드", price: 89000, desc: "..." },
  // ... 총 6개
];
export default function ProductList() {
  return (
    <section>
      <h2>상품 목록</h2>
      <div className="product-list">
        {products.map((p) => (
          <ProductCard key={p.id} product={p} />
        ))}
      </div>
    </section>
  );
}
⚠️ key는 왜 필요할까? React는 key로 "어떤 항목이 추가·삭제·이동했는지"를 구분합니다. 배열 인덱스보다 변하지 않는 고유값(id)을 쓰는 것이 안전합니다. key가 없으면 콘솔에 경고가 표시됩니다.

4. React Router로 페이지 이동

Link, useParams, useNavigate로 SPA 화면 전환을 구현합니다.

도구역할사용 위치
<BrowserRouter>라우팅 기능 제공 (최상위에서 감쌈)App
<Routes> / <Route>경로와 화면 연결App
<Link to>새로고침 없이 이동 (a 태그 대체)Header, ProductCard, NotFound
useParams()URL 파라미터(:id) 읽기ProductDetail
useNavigate()코드로 이동 (navigate("/"), navigate(-1))ProductDetail
 
export default function ProductDetail() {
  const { id } = useParams();          // "/product/3" → id === "3" (문자열!)
  const navigate = useNavigate();
  const { dispatch } = useCart();

  const product = products.find((p) => p.id === Number(id));

  if (!product) {                       // 없는 id 방어 처리
    return (
      <section>
        <p>상품을 찾을 수 없습니다.</p>
        <button onClick={() => navigate("/")}>목록으로</button>
      </section>
    );
  }

  return (
    <section className="detail">
      ...
      <button onClick={() => dispatch({ type: "ADD", product })}>장바구니 담기</button>
      <button onClick={() => navigate(-1)}>뒤로가기</button>
    </section>
  );
}
⚠️ 자주 하는 실수 useParams()의 값은 항상 문자열입니다. 숫자 id와 ===로 비교하려면 Number(id)로 변환해야 합니다. 변환하지 않으면 상품을 하나도 찾지 못합니다.
💡 404 처리 path="*"는 위의 어떤 경로와도 일치하지 않을 때 선택됩니다. 존재하지 않는 주소는 NotFound가, 존재하지 않는 상품 id는 ProductDetail 안의 if (!product)가 처리합니다.

5. useReducer로 장바구니 로직 만들기

여러 종류의 상태 변경을 하나의 리듀서 함수로 모아 관리합니다.

버튼 클릭→ dispatch({ type, ... })→ cartReducer(state, action)→ 새 state 반환→ 화면 다시 렌더링 
function cartReducer(state, action) {
  switch (action.type) {
    case "ADD": {
      const found = state.find((item) => item.id === action.product.id);
      if (found) {                                   // 이미 있으면 수량 +1
        return state.map((item) =>
          item.id === action.product.id ? { ...item, qty: item.qty + 1 } : item
        );
      }
      return [...state, { ...action.product, qty: 1 }]; // 없으면 새로 추가
    }
    case "INCREASE":
      return state.map((item) =>
        item.id === action.id ? { ...item, qty: item.qty + 1 } : item
      );
    case "DECREASE":
      return state
        .map((item) => (item.id === action.id ? { ...item, qty: item.qty - 1 } : item))
        .filter((item) => item.qty > 0);              // 0개가 되면 제거
    case "REMOVE":
      return state.filter((item) => item.id !== action.id);
    case "CLEAR":
      return [];
    default:
      return state;
  }
}
액션함께 보내는 값결과사용한 배열 메서드
ADDproduct있으면 qty+1, 없으면 qty:1로 추가find, map, spread
INCREASEidqty+1map
DECREASEidqty−1, 0이면 삭제map + filter
REMOVEid해당 상품 삭제filter
CLEAR—빈 배열—
⚠️ 불변성(immutability) item.qty++이나 state.push()처럼 기존 객체·배열을 직접 고치면 React가 변경을 감지하지 못합니다. 반드시 map, filter, 전개 연산자(...)로 새 배열·새 객체를 만들어 반환하세요.

6. Context API로 전역 상태 공유

props를 여러 단계로 내려 주지 않고, 어느 컴포넌트에서나 장바구니에 접근합니다.

  1. 만들기 — const CartContext = createContext();
  2. 공급하기 — <CartContext.Provider value={...}>로 자식들을 감쌈
  3. 꺼내 쓰기 — useContext(CartContext)를 감싼 커스텀 훅 useCart()
export function CartProvider({ children }) {
  const [cart, dispatch] = useReducer(cartReducer, [], loadCart);

  // 파생 값: state에서 계산할 수 있으면 따로 state로 두지 않는다
  const totalCount = cart.reduce((sum, item) => sum + item.qty, 0);
  const totalPrice = cart.reduce((sum, item) => sum + item.price * item.qty, 0);

  return (
    <CartContext.Provider value={{ cart, dispatch, totalCount, totalPrice }}>
      {children}
    </CartContext.Provider>
  );
}

export function useCart() {
  return useContext(CartContext);
}

어디서 무엇을 꺼내 쓰나?

컴포넌트사용하는 값용도
HeadertotalCount"장바구니 (3)" 표시
ProductCard / ProductDetaildispatchADD
CartPagecart, dispatch, totalPrice목록, 수량 변경, 총액
💡 reduce 읽는 법 cart.reduce((sum, item) => sum + item.qty, 0) — 0에서 시작해서 항목마다 qty를 더해 나간 최종 값을 돌려줍니다.

7. useEffect와 localStorage로 상태 유지

새로고침해도 장바구니가 사라지지 않도록 브라우저 저장소와 연동합니다.

function loadCart() {
  try {
    return JSON.parse(localStorage.getItem("cart")) || [];
  } catch {
    return [];                       // 저장값이 깨져 있어도 앱이 멈추지 않게
  }
}

// 세 번째 인자 = 초기화 함수 (처음 한 번만 실행되는 "지연 초기화")
const [cart, dispatch] = useReducer(cartReducer, [], loadCart);

// cart가 바뀔 때마다 저장
useEffect(() => {
  localStorage.setItem("cart", JSON.stringify(cart));
}, [cart]);
앱 시작→ loadCart()로 읽기→ 사용자가 담기/삭제→ cart 변경→ useEffect가 저장
  • localStorage는 문자열만 저장하므로 JSON.stringify / JSON.parse가 필요합니다.
  • 의존성 배열 [cart]: cart가 바뀔 때만 effect가 실행됩니다.

8. axios로 비동기 데이터 요청

외부 API를 호출하고 로딩 · 에러 · 성공 세 가지 상태를 화면에 반영합니다.

const [posts, setPosts] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(() => {
  const fetchPosts = async () => {
    try {
      const res = await axios.get(
        "https://jsonplaceholder.typicode.com/posts?_limit=10"
      );
      setPosts(res.data);                 // axios는 응답 본문을 res.data에 담아 줌
    } catch (err) {
      setError("데이터를 불러오지 못했습니다.");
    } finally {
      setLoading(false);                // 성공이든 실패든 로딩 종료
    }
  };
  fetchPosts();
}, []);                                   // [] → 처음 화면에 나타날 때 한 번만

if (loading) return <p>불러오는 중...</p>;
if (error) return <p className="error">{error}</p>;
⚠️ useEffect 콜백에 바로 async를 붙이지 않는 이유 effect 함수는 아무것도 반환하지 않거나 정리(cleanup) 함수를 반환해야 합니다. async 함수는 Promise를 반환하므로, 안쪽에 async 함수를 만들어 호출하는 패턴을 사용합니다.

9. 제어 컴포넌트와 검색 필터

입력값을 state로 관리하고, 원본 데이터에서 걸러낸 결과를 바로 보여 줍니다.

const [keyword, setKeyword] = useState("");

// 파생 데이터: posts를 직접 바꾸지 않고 렌더링할 때마다 계산
const filtered = posts.filter((post) => post.title.includes(keyword));

<input
  type="text"
  placeholder="제목 검색"
  value={keyword}                                  // state → 화면
  onChange={(e) => setKeyword(e.target.value)}     // 화면 → state
/>
<p>{filtered.length}건</p>
💡 원본은 그대로, 결과만 계산 setPosts(posts.filter(...))처럼 원본을 덮어쓰면 검색어를 지웠을 때 데이터가 돌아오지 않습니다. 필터 결과는 렌더링 중에 계산하는 파생 값으로 두세요.

12. 정리 퀴즈

질문을 클릭하면 정답이 펼쳐집니다.

Q1. ProductDetail에서 Number(id)를 빼면 어떻게 될까요? useParams()의 id는 문자열이라 p.id === "3"이 항상 false가 됩니다. 결과적으로 모든 상세 페이지에 "상품을 찾을 수 없습니다."가 표시됩니다.
Q2. 같은 상품을 두 번 담으면 장바구니 배열은 어떻게 되나요? ADD에서 find로 기존 항목을 찾으므로 항목이 두 개가 되지 않고, 기존 항목의 qty만 2가 됩니다.
Q3. 수량이 1인 상품에서 − 버튼을 누르면? DECREASE가 qty를 0으로 만든 뒤 filter(item => item.qty > 0)에서 제거되어 목록에서 사라집니다.
Q4. totalPrice를 useState로 따로 관리하지 않는 이유는? cart에서 언제든 계산할 수 있는 파생 값이기 때문입니다. 따로 state로 두면 cart와 값이 어긋날 위험이 생깁니다.
Q5. Header가 장바구니 수량을 알 수 있는 원리는? Header가 CartProvider 안쪽에 있으므로 useCart()로 Context 값 totalCount를 직접 읽습니다. cart가 바뀌면 Provider의 value가 바뀌어 Header도 다시 렌더링됩니다.
Q6. Notice의 useEffect 의존성 배열을 지우면 어떤 문제가 생길까요? 렌더링될 때마다 effect가 실행되어 요청 → setPosts → 재렌더링 → 다시 요청이 반복되는 무한 요청이 발생합니다.
Q7. 새로고침해도 장바구니가 유지되는 이유는? cart가 바뀔 때마다 useEffect가 localStorage에 저장하고, 앱이 시작될 때 useReducer의 초기화 함수 loadCart가 저장된 값을 읽어 오기 때문입니다.
